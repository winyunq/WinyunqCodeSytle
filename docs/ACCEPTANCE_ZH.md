## 本轮已执行的三个任务

### 内容迁移

本地JSON/CSV的既有单位和顾问表；源文件是已导出的普通JSON，而不是实际星际地图。通过真实MCP导入：一条更新、一条新增，未提供的原记录完整保留，运行源码hash不变，再次导入unchanged。内容模式尝试新增C++管理器被拒绝。

### 复用现有选择系统

在便携原生C++测试替身中，选择数量依次改变3/9/0/1/17。测试实际结果、65536个世界实体的查询次数、复制次数及分配次数。直接使用现有view.Num成功；世界重扫、复制集合、静态旧缓存失败并回滚。保留负对照：只做编译时重扫实现可以通过。没有声称这些断言会自动生成或适用于全部UE代码。

### 扩展原责任系统

`return x+0`缩短成功；只提交`A::ClampStep`的CPP定义，自动同步A.h且复用A.Normalize，真实编译和断言通过。不能外推为复杂模板/RPC/所有调用者重构都支持。

详细请求在evidence/replay，窗口操作在evidence/gui。GUI由测试驱动操作真实窗口，不把脚本点击当作本人认证。

## Windows / 真实 UE 本机需执行

先在版本控制干净的副本上工作，不直接套用演示profile到生产工程。

1. 安装Python/Tk、选择真实Doxygen，运行GUI。核对四工具、项目根、profile和状态目录。Windows安装器不是本轮实测项目。
2. 给既有DataTable声明真实Name及全部导出字段。连接编辑器，读取两条已存在行并核对UStruct。不存在/断开编辑器时必须明确报错。
3. 更新一条现有行、增加一条真实允许的新行。核对省略行/字段、资源引用和游戏原消费者读取结果；再次导入不得产生新变化。
4. 未保存资产或PIE中请求写入，应拒绝。另开窗口修改表之后，旧计划应拒绝。
5. 模拟不可解析引用或错误类型，应拒绝而不是生成占位对象。模拟保存失败，核对回执与before.json；不允许编写C++补偿导入错误。
6. 为真实源码维护profile接入UBT/UHT和相关任务验收。没有命令时只能说结构检查，不说编译通过。实际Codex连接同一入口，核对该宿主对单份structuredContent的支持；必要时选择单份text模式。
7. 试独立Delete：没批准失败；GUI展示全量具体差异后批准才成功。修改profile/锁/源码后旧计划失效。锁不能靠scope/别名绕过。

## 不应据此得出的结论

本包没有跑完整UE项目、实际Codex宿主或Windows安装；没有导入用户的地图；未证明任意代码都可控，也未证明可以自动识别全部过度设计。可复现的改进是：原来缺失的已绑定数据路径可执行，错误域不能自升级，实际任务成本断言能约束提交。
